01 / A modell körüli rendszer

Mi a harness?

A harness az a futtató réteg a modell körül, amely előkészíti a bemenetet, végrehajtja a jóváhagyott műveleteket, és visszaadja az eredményt.

Feladat„Tegyél status oszlopot a CSV-be.”
→
ModellMűveletet javasol vagy választ ad.
→
HarnessFájlt olvas, módosít, tesztet futtat.
→
KörnyezetRepository, futtató és tesztadat.
A harness engineering ezeknek az eszközöknek, kontextusszabályoknak és visszajelzési pontoknak a megtervezése és mérése.

Részletes magyarázat

Coding agent alatt itt a működő rendszert értjük: nyelvi modell, harness, hozzáférhető eszközök és környezet együtt. A modell a következő lépést választja, az alkalmazás valósítja meg a tényleges hatást.

A szó szűkebb jelentésében a futtató kódot jelöli. Az OpenAI mérnöki esettanulmánya a repository környezetét és az ellenőrzési lehetőségeket is a harness engineering részeként kezeli.

03 / Custom harness

Egy saját loopban a budget és a stop is szabály

A budget megszabhatja a turnök számát és az eltelt időt. A stop condition eldönti, mikor adható vissza ellenőrzött eredmény.

Szemléltető pszeudokód

while budget.remains():
    action = model.next(context, tools)
    if action.is_done:
        result = verify(workspace)
        if result.passed:
            return patch_and_evidence()
    else:
        result = run_allowed(action)
    context.add(result.summary)
return incomplete_with_trace()

Ugyanez a CSV-példában

A modell késznek jelenti az első patchet. A verifier négy mezőt olvas a három helyett. A következő turn megkapja ezt a hibát.

Ha a budget elfogy, a harness rögzíti a patch állapotát és az utolsó teszthibát.

Részletes magyarázat

A budget ellenőrzése a valódi implementációban a tool futási idejére is kiterjed. A run_allowed az adott tool és argumentum policyját érvényesíti. Ez olvasható algoritmusváz, a konkrét SDK függvénynevei eltérnek.
